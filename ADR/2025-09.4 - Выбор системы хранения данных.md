**Дата:** 26 ноября 2025 г.
**Статус:** Принято

**Контекст:**

Нам нужна надежная и масштабируемая система хранения данных, способная обрабатывать различные типы данных: структурированные данные пользователей и бронирований, полнотекстовый поиск по каталогу ТС, кэширование и сессии.

Рассмотренные варианты:

1. **PostgreSQL:** Реляционная БД для структурированных данных
2. **MongoDB:** Документная БД для гибкости схемы
3. **Redis**: In-memory хранилище для кэша и сессий
4. **Elasticsearch:** Для полнотекстового поиска и аналитики
5. **ClickHouse:** Для аналитических запросов и отчетности

Решение:

Выбран полиглотный подход с использованием:
- **PostgreSQL** - для основных данных (пользователи, ТС, бронирования, платежи)
- **Redis** - для кэширования и сессий
- **Elasticsearch** - для поиска по каталогу ТС
- **Amazon S3** - для хранения медиафайлов

**Обоснование:**

- **PostgreSQL:** Надежность, ACID-транзакции, поддержка JSON, отличная производительность
- **Redis:** Высокая скорость для кэша, сессий и очередей
- **Elasticsearch:** Оптимизирован для полнотекстового поиска и агрегаций
- **S3:** Надежное и масштабируемое хранилище для медиа
- **Eventual Consistency:** Поисковый индекс может обновляться асинхронно

**Последствия:**

- Разные сервисы используют разные хранилища согласно их потребностям
- Необходимость синхронизации данных между PostgreSQL и Elasticsearch
- Реализация шаблона CQRS для разделения операций записи и чтения
- Регулярное резервное копирование и мониторинг всех хранилищ
