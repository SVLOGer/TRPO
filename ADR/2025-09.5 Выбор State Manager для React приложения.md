**Дата:** 26 ноября 2025 г.
**Статус:** Принято

**Контекст:**

Для клиентского React приложения сервиса аренды транспортных средств необходимо выбрать решение для управления состоянием. Приложение включает сложные бизнес-процессы: поиск и фильтрация транспорта, процесс бронирования, управление корзиной, пользовательские сессии, кэширование данных. Требуется надежное и предсказуемое управление состоянием с хорошей поддержкой TypeScript и возможностями отладки.

**Рассмотренные варианты:**

1. **Redux Toolkit + RTK Query:** Современный подход к Redux с уменьшенным boilerplate
2. **Zustand:** Минималистичная библиотека с простым API
3. **React Context + useReducer:** Встроенное решение React
4. **MobX:** Реактивное управление состоянием
5. **TanStack Query + Zustand:** Комбинированный подход

**Решение:**

Выбран Redux Toolkit + RTK Query.

**Обоснование:**

- **Предсказуемость состояния:** Strict mode и иммутабельные обновления обеспечивают детерминированное поведение
- **DevTools:** Богатые возможности отладки и time-travel debugging
- **TypeScript поддержка:** Отличная типизация из коробки
- **Стандартизация:** Единый подход для всех команд
- **RTK Query:** Встроенное решение для кэширования серверного состояния
- **Экосистема:** Большое количество middleware и инструментов

Недостатки решения:

- **Bundle size:** Увеличение размера приложения
- **Boilerplate:** Больше кода по сравнению с альтернативами

**Последствия:**

- **Стандартизация:** Разработать guidelines по структуре slices и actions
- **Производительность:** Настроить мемоизацию селекторов с Reselect
- **Тестирование:** Внедрение unit-тестов для reducers и интеграционных тестов для store
- **Мониторинг:** Использование Redux DevTools для отладки в production
