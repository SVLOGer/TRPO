**Дата:** 26 ноября 2025 г.
**Статус:** Принято

**Контекст:**

Для обеспечения качества и надежности распределенной системы нам необходим комплексный подход к автоматическому тестированию, покрывающий все уровни приложения и интегрированный в процесс CI/CD.

**Рассмотренные варианты:**

1. **Unit-тесты:** JUnit 5, Kotest, Jest, React Testing Library
2. **Интеграционные тесты:** Testcontainers, Spring Boot Test
3. **API-тесты:** Postman, REST Assured, Karate
4. **E2E-тесты:** Selenium, Cypress, Playwright, Appium
5. **Нагрузочное тестирование:** k6, Gatling, JMeter

**Решение:**

Выбран следующий стек:
- **Unit-тесты:** Kotest + MockK для бэкенда, Jest + React Testing Library для фронтенда
- **Интеграционные тесты:** Testcontainers + Spring Boot Test
- **API-тесты:** Postman + Newman
- **E2E-тесты:** Playwright для веба, Detox для мобильных приложений
- **Нагрузочное тестирование:** k6

**Обоснование:**

- **Kotest:** Более выразительный синтаксис чем JUnit 5, хорошая поддержка Kotlin
- **Testcontainers:** Тестирование против реальных баз данных в изоляции
- **Postman/Newman:** Удобство разработки тестов и интеграция в CI/CD
- **Playwright:** Высокая скорость и надежность E2E-тестов
- **k6:** Современный инструмент нагрузочного тестирования с хорошей интеграцией

**Последствия:**

- Необходимо настроить pipeline в CI/CD для выполнения всех типов тестов
- Требуется выделить время на написание и поддержку тестов
- Коллекции Postman должны поддерживаться как часть документации API
- E2E-тесты выполняются на staging-окружении перед деплоем в production
